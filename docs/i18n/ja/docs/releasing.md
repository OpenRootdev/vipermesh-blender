# 公開コネクタのリリースチェックリスト

公開リポジトリは `config/public-blender-connector-files.json` から生成します。非公開リポジトリの履歴をフォークしたりコピーしたりしないでください。

<a id="current-release"></a>
## 現在のリリース

- リポジトリ: https://github.com/OpenRootdev/vipermesh-blender
- リリース対象: https://github.com/OpenRootdev/vipermesh-blender/releases/tag/v1.3.0
- ソースのリリース対象: `v1.3.0`
- Blender 互換性の対象: 5.2
- CI: 独立した型チェック、適合性テスト、ビルド、パッケージ検証、npm 監査、アドオンの Python コンパイル
- 過去の実環境検証 (v1.2.0): 持続的な stdio MCP の検出、シーンの呼び出し、状態変更、段階的なプレビューと最終処理、保存、ローカルガイダンス、`execute_code` によるフォールバック
- 現在の起動検査: 独立したパッケージの適合性、インライン画像転送、レンダリングのみの段階処理と既存表示の保持、空間検証失敗時の出力抑止、依存関係の監査、Python コンパイル、デスクトップとモバイルでのサイト確認。エージェント全体の実環境性能は、次回のデモ試験で評価します。

<a id="before-export"></a>
## エクスポート前

- `npm run validate:public-blender-connector` を実行します。
- ポータブル MCP ゲートウェイとアドオン UI の対象を絞ったテストを実行します。
- `python -m py_compile` でアドオンをコンパイルします。
- 生成されたアドオンを現在の Blender 5.2 リリースにインストールします。
- Stopped、Ready、Agent connected、Error の UI 状態を確認します。
- 新しい MCP クライアントから、初期設定、シーン検査、状態変更、プレビュー確認、最終レンダリング、保存、終了を確認します。

<a id="export-safety"></a>
## エクスポートの安全性

- マニフェストの項目だけをエクスポートします。
- 出力先の重複、欠落したファイル、絶対パス、ディレクトリの遡及、非公開アプリケーションのパス、秘密情報、認証情報、内部ベンチマークの証拠、競合プロバイダー固有のコードを拒否します。
- GitHub リポジトリを作成する前に、生成したディレクトリを再度検査します。
- 非公開コミットを引き継がない新しいリポジトリとして、`Ker102/vipermesh-blender` を作成します。

<a id="release"></a>
## リリース

1. 生成したディレクトリで依存関係をインストールし、`npm run check` を実行します。
2. アドオンをリリース成果物としてパッケージ化します。
3. コネクタのバージョンにタグを付けます。
4. パッケージの内容を確認してから MCP パッケージを公開します。
5. 非公開の ViperMesh 製品が使用するコネクタを、リリース済みバージョンに固定します。
6. 公開のインストール経路を独立して確認します。
7. その後に限り、ViperMesh 製品リポジトリの公開範囲を変更します。
